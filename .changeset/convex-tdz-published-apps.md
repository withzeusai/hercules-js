Prevent a "Cannot access 'X' before initialization" crash in published apps. The plugin now isolates the Convex client into its own production chunk, so its module-scoped bindings (the react hooks, value codecs, and the `anyApi` proxy behind `_generated/api`) initialize once, before the lazily-loaded route chunks that import them. Left to Rollup's default splitting, those bindings could be hoisted into a shared chunk that formed a circular reference with a route chunk; in the minified production build the reference was read before initialization, so the published app threw during a lazy route load and rendered its error boundary. The dev server serves native ESM without chunking, so the crash only ever appeared in the published bundle. The isolation is decided per build environment, so Vite's multi-environment builder no longer leaks a `manualChunks` callback into an environment that disables code splitting (for example an `environments.ssr` with `output.codeSplitting: false`), which would otherwise abort the build. Convex is also detected when it is provided transitively (resolvable from the app root) rather than listed directly in the app's `package.json`; that resolution targets Convex's package entry, which is always exported, rather than a `convex/package.json` subpath that current Convex releases no longer expose. The grouping applies only to environments that actually code-split. SSR builds (whether started with `--ssr` or configured through `build.ssr` in the config file, including a webworker target), library builds, any output with `inlineDynamicImports`, an explicit `output.codeSplitting: false`, and the single-bundle `iife`/`umd` formats all disable code splitting, where a `manualChunks` callback is invalid; the plugin now detects each of these and leaves them untouched instead of emitting an invalid config. When an app sets `output.codeSplitting` explicitly (boolean `true` or the object form) or uses the deprecated `output.advancedChunks`, where Rolldown ignores `manualChunks`, the isolation is applied as a high-priority code-splitting group with every size limit pinned and recursive dependency inclusion forced, so Convex is always emitted as one self-contained chunk even when the app sets a large global `minSize`/`minModuleSize`, a small global `maxSize`/`maxModuleSize`, or disables `includeDependenciesRecursively`. For an app that does not depend on Convex, or a build that does not code-split, the plugin is a pure no-op, touching neither the split config nor `optimizeDeps`.
